# FHIR UI

FHIR UI is an open-source shadcn registry of React inputs for FHIR R4 data structures. It includes first-class Indonesian healthcare mappings while making a deliberate distinction between typed data, tested conversion logic, and profile validation.

## Install in 30 seconds

Start with a shadcn-enabled React project, then add a component directly from the repository-backed registry:

```bash
pnpm dlx shadcn@latest add https://raw.githubusercontent.com/vamioshq/fhir-ui/main/public/r/fhir-date-input.json
```

The registry item installs its required shadcn primitives and npm dependencies. Use `npm exec`, `npx`, or `bunx` instead if that matches your project.

```tsx
import { FHIRDateInput } from "@/registry/fhir-ui/fhir-date-input"

<FHIRDateInput value={birthDate} onChange={setBirthDate} showLabel label="Date of birth" />
```

## Know what is guaranteed

Components carry explicit evidence labels. “FHIR-shaped” means the value uses a FHIR-compatible structure; it does not claim that your final resource satisfies every invariant or implementation profile.

[Review the full conformance matrix](/docs/conformance) before selecting components for a production workflow.

## Current project boundary

- Search-driven resource inputs expose adapter contracts and currently include mock helpers.
- SATUSEHAT mappings are not blanket claims of profile validation.
- Applications own server validation, authorization, consent, auditability, and clinical governance.
- Accessibility is an engineering goal; complete automated and assistive-technology coverage is still planned.
